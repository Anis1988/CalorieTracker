# Working on this repo

- **Keep the Guide tab up to date.** Every change that adds or changes a user-visible feature must also update `src/pages/Guide.tsx` in the same commit: plain everyday words, and a live example built from the app's own components (made-up data, no working buttons).
- Push directly to `main` (the owner deploys from it via Vercel).
- Do not add automated tests unless asked.
- New features: describe them and get the owner's OK before building. Bug fixes can go straight in.
- Phone-friendly is required: check a 390px-wide layout for any UI change, in light and dark.
- Everything the owner can change lives in Settings (`Settings` in `src/lib/types.ts`, `withDefaults` for old saves, `src/pages/Settings.tsx`). Settings are stored on the server (`ct:settings`), the same on every device.
- Hosting is Vercel: `api/*.ts` are the server functions (Web `GET`/`POST` handlers), `server/` the shared code, Upstash Redis the storage (keys in `server/store.ts`). Server imports must end in `.js`. Vercel Hobby allows 12 functions; there are 6 (`analyze`, `entries`, `body`, `settings`, `beauty`, `cooking`). Request limit 4.5 MB: photos are shrunk on the device first (`src/lib/image.ts`: 1280px for the AI, 360px kept).
- Access: one owner, `APP_ACCESS_TOKEN` (header `x-access-token`, kept on the device as `ct.code`), same-origin + rate limit (`server/guard.ts`).
- 🤖 AI (owner's rule, like the other apps): free Gemini first, Claude (paid) as the backup when Gemini is over its daily limit, not set up or fails (`analyze` in `server/ai.ts`; switchable in Settings → AI). Each AI has its own daily limit (`ct:ai:<day>:<provider>`). The same photo/words are never paid twice (`ct:cache:<sha256>`, `ai.rememberDays`). Barcodes (Open Food Facts, called from the device), favorites and recent meals never use the AI. One AI read gives items + health score + notes + tips.
- Nutrition maths in `src/lib/nutrition.ts` (Mifflin–St Jeor, activity factors, 7,700 kcal/kg, floors 1,500/1,200, macro plans, units). The newest logged weight updates `profile.weightKg`.
- Dates are the phone's local days (`src/lib/date.ts`); entries live in one hash per month (`ct:month:YYYY-MM`), water per month, weights and favorites in one hash each.
- Look: "Fresh Glass" (lime #bef264 → amber #fbbf24 accent, night #07090c / light #f3f5ef, glass `.card`, `.tap` effect, sliding `Seg`/tab pill, `.switch`). Light/dark: `darkMode: 'class'`, Settings → Look (auto follows the phone; `ct.theme` applied before first paint in `index.html`). Macro colours checked for colour-blind readers: protein `--protein`, carbs `--carbs`, fat `--fat` (different steps in dark), always shown with their name/number. Motion only transform/opacity, off under `prefers-reduced-motion`.
- 📱 Android app = branch `android` (Capacitor 8, `capacitor.config.ts` with `CapacitorHttp` so requests go to the live site without CORS, `android/`, workflow `android.yml` → release `android-latest`, `CalorieTracker.apk`, fixed sideload keystore so updates install in place). The app asks for the site address once (`src/lib/native.ts`, default `VITE_API_BASE` = Actions variable `CALORIE_URL`), update banner (`AppUpdateCheck`), back button closes panels → Today → minimise, downloads go through the Share menu. Vercel skips the `android` branch (`vercel.json`). After pushing to `main`, merge `main` into `android`.
- 💄 Beauty side (owner's choice: "like a different app"): the Food | Beauty switch at the top (`Main` in `src/App.tsx`, `ct.space` on the device, class `beauty` on <html> set before first paint) swaps the bottom bar (Food: Today · History · 📸 · Weight · Settings; Beauty: Check · My shelf · 📸 · Skin · Settings), the look (pink/orchid: `.beauty` CSS vars in `src/index.css`, `Glow`), the guide (`BeautyGuide`) and which Settings sections show (`Settings space=`). Off with `settings.beauty.on`. Skin profile = `Settings.beauty`. Product check: `api/beauty.ts` → `checkProduct` (`server/beauty.ts`), up to 3 photos, same `ask()` as food (`server/ai.ts`: free Gemini first, Claude backup, limits, cache incl. the profile). The avoid list is matched with plain text (`src/lib/avoid.ts`, label names like parfum) after the AI and forces "Not for you" (the AI can't override it). My shelf = `ct:shelf` (status, opened date + PAO → use-by), routine built from Using/Loved (`routine` in `src/components/Beauty.tsx`). Guidance only, never medical advice.
- 🍳 Cooking side (owner's request): third space in the switch (🥗 Calories | 💄 Beauty | 🍳 Cooking; the food side is called "Calories" on screen, `food` in code). Orange look (`.cooking` vars), tabs Cook · Recipes · 📸 · Pantry · Settings. `api/cooking.ts` → `findRecipes` (`server/cooking.ts`, typed ingredients + up to 3 photos + pantry + `Settings.cooking`, "Fit my day" = what's left in Calories, 16k tokens, maxDuration 300) and `seeIngredients` (pantry scan). Allergies re-checked with plain words after the AI (`src/lib/allergy.ts`): flagged ⚠️ and sorted last. Recipes `ct:recipes` (fav, rating, cooked), pantry `ct:pantry`, shopping list `ct:shop`. Cook mode (portal, wake lock, step timers), servings scale the amounts (`amount`), "Log this meal" adds a Calories entry without AI. The AI picked in Settings → AI is used by all three sides (owner's rule).
- 🧪 Beauty mixing check: free rules (`src/lib/clash.ts`: actives found in ingredients → known pairs, ⛔/⚠️/ℹ️) on Using/Loved products (Skin tab) and the product being checked vs the shelf (`ShelfClash`). 🧾 Receipt scan (Pantry, camera; gallery link too): `seeIngredients(…, 'receipt')` (AI skips non-food, then the `NOT_FOOD` word list) → straight into the pantry with Undo (owner's choice), ticks matching shopping-list items. Fridge snap keeps its preview. 📱 Android home-screen widget (android branch only).
- 🖼️ Recipe photos (owner's request, free): `server/photo.ts` gathers candidates from Unsplash (`UNSPLASH_ACCESS_KEY`, first; download ping on use), Pixabay (`PIXABAY_API_KEY`, the owner's key), Pexels (`PEXELS_API_KEY`) and Wikimedia Commons, scores each on the dish's words (AI `photoQuery` + title) and only uses a clear match (no generic photos: none → 🍽️). Cached 30 days per dish (`ct:cache:photo2:…`), `POST /api/cooking {photo: {title, cuisine, query, skip}}` (skip = "↻ Another photo"). `Recipe.photo` (undefined = not looked yet, null = none, `v: 2` = matched; older ones are looked for again), small on cards, banner in the recipe, `PhotoViewer` full screen (ui.tsx, portal, tap to zoom). Credit shown.
- 🎨 AI recipe pictures (owner's choice "C"): `Settings.cooking.pictures` real / opened (default) / all, `aiPicsPerDay` (10), `imageModel`. `server/draw.ts` → Gemini image (`GEMINI_API_KEY`, about 4 cents, counted as `ct:ai:<day>:image`), `POST /api/cooking {draw}` returns the picture once; the device shrinks it (400/1280 JPEG) and sends `{drawn}`, kept as `ct:photo:draw-<key>-t/-f` (10 years, key = hash of title + summary, so a dish is never paid twice). `RecipePhoto.thumb/full = 'ai:<id>'` resolved by `useSrc` (GET /api/entries?photo=), `ai: true`.
- `Sheet` and cook mode render in a portal (document.body), so a panel opened from a panel still covers the screen.
- The app gives estimates, never medical advice.
